# Native wrapper (Capacitor)

Keystone is wrapped for iOS and Android with [Capacitor](https://capacitorjs.com) — the web app
itself is unchanged; Capacitor just packages the existing Vite build (`dist/`) into a native
shell for each store. What's here:

- `capacitor.config.ts` — app ID, name, and web asset directory.
- `ios/` — a real Xcode project (`ios/App/App.xcworkspace`).
- `android/` — a real Android Studio / Gradle project.

Both were generated by `npx cap add ios` / `npx cap add android` against this repo's actual
build, not hand-written — they're standard Capacitor scaffolding.

## Before you submit anywhere: the app ID

`capacitor.config.ts`'s `appId` is currently the placeholder `com.keystone.app`. This becomes
your bundle identifier (iOS) / application ID (Android) — **it's permanent once you first submit
a build to either store.** Confirm or change it to your real reverse-DNS identifier (e.g.
`com.yourcompany.keystone`) before doing anything else here, then re-run `npx cap sync` so both
native projects pick up the change.

## Building — needs tools this environment doesn't have

Generating the project folders doesn't require Xcode or Android Studio, but actually compiling,
signing, and running a build does — that has to happen on your own machine:

- **iOS** needs a Mac with Xcode installed. Run `npm run cap:open:ios` to open the project, then
  set your Apple Developer team under Signing & Capabilities before building to a simulator or
  device.
- **Android** needs Android Studio (works on Mac, Windows, or Linux). Run
  `npm run cap:open:android` to open the project.

## The day-to-day workflow

Any time the web app changes, run:

```
npm run cap:sync
```

before opening either native project — this rebuilds the web bundle and copies it into both
`ios/App/App/public` and `android/app/src/main/assets/public`, and re-syncs any Capacitor plugin
config. Those copied folders are gitignored (Capacitor's own scaffolding already excludes them)
— only the actual project files are tracked.

## Icons and splash screen

The app already has a source icon at `appstore-assets/icon-1024.png` (and `public/icon.svg`).
Capacitor's companion tool, `@capacitor/assets`, generates every required native icon and splash
size from one source image — not run yet; that's the next step once the app ID above is settled.

## What this scaffolding doesn't cover yet

This is the native *shell* — the following are separate, larger pieces of work (see the
Development Finalization & QA phase of the launch roadmap):

- **Native plugins** — Haptics, Status Bar, Splash Screen, Push Notifications, and Geolocation
  all have official Capacitor plugins that make reminders, arrival alerts, and the app's existing
  haptic feedback behave natively instead of falling back to web APIs.
- **In-app purchase** — the Pro unlock currently sells through Stripe web checkout inside the
  app, which risks App Store rejection (guideline 3.1.1). Needs StoreKit (iOS) and Play Billing
  (Android) wired up, validating against the same `isPro` flag the backend already uses.
- **Offline behavior inside the native WebView** — worth verifying explicitly rather than
  assuming: Capacitor serves the bundled web assets from local disk inside the native app, which
  is a different loading path than the PWA's service worker (`public/sw.js`) was written for.
